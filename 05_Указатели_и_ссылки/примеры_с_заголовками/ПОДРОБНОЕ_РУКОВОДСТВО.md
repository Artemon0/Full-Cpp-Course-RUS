## Что такое заголовочные файлы

**Заголовочный файл (.h или .hpp)** - это файл, который содержит **объявления** (declarations), но не **определения** (definitions).

### Аналогия
Представьте книгу:
- **Оглавление** = `.h` файл (что есть в книге)
- **Главы с текстом** = `.cpp` файл (как это работает)

## .h vs .hpp - в чем разница

### Краткий ответ
**Технически - никакой разницы!** Оба расширения работают одинаково. Это просто соглашение об именовании.

### Подробное объяснение

#### `.h` - традиционное расширение
```cpp
// math.h
int add(int a, int b);
```

**Используется для:**
- Заголовков C (обязательно)
- Заголовков C++ (традиционно)
- Совместимости с C и C++

**История:** Пришло из языка C, где все заголовки имели расширение `.h`

#### `.hpp` - C++ специфичное расширение
```cpp
// math.hpp
int add(int a, int b);
```

**Используется для:**
- Только C++ кода
- Явного указания, что это C++ заголовок
- Отличия от C заголовков

**История:** Появилось позже для явного обозначения C++ файлов

### Сравнительная таблица

| Аспект | .h | .hpp |
|--------|----|----- |
| **Совместимость с C** | ✅ Да | ❌ Нет (подразумевается C++) |
| **Работает в C++** | ✅ Да | ✅ Да |
| **Стандартная библиотека C++** | ❌ Нет (без расширения) | ❌ Нет |
| **Традиционность** | ✅ Более традиционно | ⚠️ Менее традиционно |
| **Явность** | ⚠️ Неясно C или C++ | ✅ Явно C++ |

### Примеры из реальных проектов

#### Используют .h:
- **Qt Framework** - `QWidget.h`, `QString.h`
- **OpenGL** - `gl.h`, `glut.h`
- **SDL** - `SDL.h`
- **Большинство старых проектов**

#### Используют .hpp:
- **Boost** - `boost/algorithm.hpp`
- **Некоторые современные библиотеки**
- **Проекты, где важно отличить C от C++**

### Стандартная библиотека C++

Интересный факт: стандартная библиотека C++ **не использует расширения вообще**:
```cpp
#include <iostream>  // Без .h или .hpp
#include <vector>    // Без .h или .hpp
#include <string>    // Без .h или .hpp
```

А старые C заголовки в C++ имеют префикс `c`:
```cpp
// C версия
#include <stdio.h>
#include <math.h>

// C++ версия (те же функции, но в namespace std)
#include <cstdio>
#include <cmath>
```

### Когда использовать что?

#### Используйте `.h` если:
- ✅ Пишете код, совместимый с C и C++
- ✅ Работаете над проектом, где уже используется `.h`
- ✅ Хотите следовать традициям
- ✅ Не хотите думать о выборе расширения

#### Используйте `.hpp` если:
- ✅ Пишете чисто C++ код (с классами, шаблонами и т.д.)
- ✅ Хотите явно показать, что это C++
- ✅ Работаете над проектом, где используется `.hpp`
- ✅ Хотите отделить C++ заголовки от C заголовков в одном проекте

### Смешанный проект (C и C++)

Если в проекте есть и C, и C++ код:
```
project/
├── math.h          # C заголовок (можно использовать из C и C++)
├── geometry.hpp    # C++ заголовок (только для C++)
├── math.c          # C реализация
└── geometry.cpp    # C++ реализация
```

### Другие расширения

Существуют и другие варианты (редко используются):
- `.hh` - альтернатива `.hpp`
- `.hxx` - еще одна альтернатива
- `.h++` - старое обозначение C++
- `.H` - с заглавной буквы (некоторые Unix системы)

### Рекомендация для этого курса

**Мы используем `.h`** потому что:
1. Это самое распространенное расширение
2. Работает везде
3. Проще для начинающих
4. Традиционно и понятно

### Практический пример

Оба варианта работают одинаково:

**Вариант 1: С .h**
```cpp
// Calculator.h
#ifndef CALCULATOR_H
#define CALCULATOR_H

class Calculator {
public:
    int add(int a, int b);
};

#endif
```

**Вариант 2: С .hpp**
```cpp
// Calculator.hpp
#ifndef CALCULATOR_HPP
#define CALCULATOR_HPP

class Calculator {
public:
    int add(int a, int b);
};

#endif
```

Оба компилируются и работают **абсолютно одинаково**!

### Вывод

🎯 **Главное правило:** Выберите один стиль и придерживайтесь его во всем проекте!

- Если проект использует `.h` - используйте `.h`
- Если проект использует `.hpp` - используйте `.hpp`
- Если начинаете новый проект - выберите то, что вам больше нравится

**Консистентность важнее, чем выбор конкретного расширения!**

## Зачем они нужны

### 1. Разделение интерфейса и реализации
```cpp
// math.h - ИНТЕРФЕЙС (что можно делать)
int add(int a, int b);

// math.cpp - РЕАЛИЗАЦИЯ (как это работает)
int add(int a, int b) {
    return a + b;
}
```

### 2. Переиспользование кода
Один `.h` файл можно подключить в разные `.cpp` файлы:
```cpp
// file1.cpp
#include "math.h"
int result1 = add(5, 3);

// file2.cpp
#include "math.h"
int result2 = add(10, 20);
```

### 3. Ускорение компиляции
Изменения в `.cpp` не требуют перекомпиляции всех файлов, которые используют этот модуль.

### 4. Документация
`.h` файл служит документацией - показывает, что доступно для использования.

## Структура .h файла

### Базовая структура
```cpp
#ifndef FILENAME_H    // 1. Защита от повторного включения
#define FILENAME_H

// 2. Подключение необходимых заголовков
#include <iostream>
#include <string>

// 3. Объявления констант
const double PI = 3.14159;

// 4. Объявления функций
int add(int a, int b);
double multiply(double a, double b);

// 5. Объявления классов
class Calculator {
private:
    double result;
    
public:
    Calculator();
    ~Calculator();
    
    double add(double a, double b);
    double getResult() const;
};

// 6. Inline функции (маленькие)
inline int square(int x) {
    return x * x;
}

#endif // FILENAME_H
```

## Include Guards

### Проблема без Include Guards
```cpp
// math.h
int add(int a, int b);

// file1.h
#include "math.h"

// file2.h
#include "math.h"

// main.cpp
#include "file1.h"
#include "file2.h"  // ОШИБКА: add объявлен дважды!
```

### Решение: Include Guards
```cpp
#ifndef MATH_H
#define MATH_H

int add(int a, int b);

#endif // MATH_H
```

### Современная альтернатива: #pragma once
```cpp
#pragma once

int add(int a, int b);
```

**Рекомендация:** Используйте `#ifndef/#define/#endif` для максимальной совместимости.

## Что писать в .h, а что в .cpp

### ✅ В .h файле (ОБЪЯВЛЕНИЯ):

#### 1. Объявления функций
```cpp
int add(int a, int b);
void print(const std::string& text);
```

#### 2. Объявления классов
```cpp
class Student {
private:
    std::string name;
    int age;
    
public:
    Student(std::string n, int a);
    void showInfo() const;
};
```

#### 3. Inline функции (маленькие)
```cpp
inline int square(int x) {
    return x * x;
}
```

#### 4. Константы
```cpp
const double PI = 3.14159;
const int MAX_SIZE = 100;
```

#### 5. Шаблоны (templates)
```cpp
template <typename T>
T maximum(T a, T b) {
    return (a > b) ? a : b;
}
```

### ✅ В .cpp файле (ОПРЕДЕЛЕНИЯ):

#### 1. Реализация функций
```cpp
#include "math.h"

int add(int a, int b) {
    return a + b;
}
```

#### 2. Реализация методов классов
```cpp
#include "Student.h"

Student::Student(std::string n, int a) : name(n), age(a) {}

void Student::showInfo() const {
    std::cout << "Name: " << name << ", Age: " << age << std::endl;
}
```

#### 3. Глобальные переменные
```cpp
int globalCounter = 0;
```

## Примеры от простого к сложному

### 🟢 Уровень 1: Простые функции (math.h/cpp)

**math.h:**
```cpp
#ifndef MATH_H
#define MATH_H

// Простые математические функции
int add(int a, int b);
int subtract(int a, int b);
int multiply(int a, int b);
double divide(double a, double b);

#endif
```

**math.cpp:**
```cpp
#include "math.h"

int add(int a, int b) {
    return a + b;
}

int subtract(int a, int b) {
    return a - b;
}

int multiply(int a, int b) {
    return a * b;
}

double divide(double a, double b) {
    if (b != 0) return a / b;
    return 0;
}
```

**Использование:**
```cpp
#include "math.h"

int main() {
    int result = add(5, 3);  // 8
    return 0;
}
```

### 🟡 Уровень 2: Простой класс (Student.h/cpp)

**Student.h:**
```cpp
#ifndef STUDENT_H
#define STUDENT_H

#include <string>

class Student {
private:
    std::string name;
    int age;
    double gpa;
    
public:
    // Конструктор
    Student(std::string name, int age, double gpa);
    
    // Геттеры
    std::string getName() const;
    int getAge() const;
    double getGPA() const;
    
    // Сеттеры
    void setGPA(double gpa);
    
    // Методы
    void showInfo() const;
    bool isExcellent() const;
};

#endif
```

**Student.cpp:**
```cpp
#include "Student.h"
#include <iostream>

Student::Student(std::string name, int age, double gpa) 
    : name(name), age(age), gpa(gpa) {}

std::string Student::getName() const {
    return name;
}

int Student::getAge() const {
    return age;
}

double Student::getGPA() const {
    return gpa;
}

void Student::setGPA(double gpa) {
    if (gpa >= 0 && gpa <= 5) {
        this->gpa = gpa;
    }
}

void Student::showInfo() const {
    std::cout << "Student: " << name 
              << ", Age: " << age 
              << ", GPA: " << gpa << std::endl;
}

bool Student::isExcellent() const {
    return gpa >= 4.5;
}
```

## Частые ошибки

### ❌ Ошибка 1: Определение функции в .h файле
```cpp
// math.h - НЕПРАВИЛЬНО!
int add(int a, int b) {
    return a + b;  // Определение в .h файле
}
```

**Проблема:** При подключении в несколько файлов будет ошибка множественного определения.

**Решение:**
```cpp
// math.h - ПРАВИЛЬНО
int add(int a, int b);  // Только объявление

// math.cpp
int add(int a, int b) {
    return a + b;  // Определение в .cpp файле
}
```

---

### ❌ Ошибка 2: Забыли Include Guards
```cpp
// math.h - НЕПРАВИЛЬНО!
int add(int a, int b);
```

**Решение:**
```cpp
// math.h - ПРАВИЛЬНО
#ifndef MATH_H
#define MATH_H

int add(int a, int b);

#endif
```

---

### ❌ Ошибка 3: Циклические зависимости
```cpp
// A.h
#include "B.h"
class A { B* b; };

// B.h
#include "A.h"
class B { A* a; };
```

**Решение:** Используйте forward declaration
```cpp
// A.h
class B;  // Forward declaration
class A { B* b; };

// B.h
class A;  // Forward declaration
class B { A* a; };
```

---

### ❌ Ошибка 4: Забыли подключить .cpp при компиляции
```bash
# НЕПРАВИЛЬНО
g++ main.cpp -o program

# ПРАВИЛЬНО
g++ main.cpp math.cpp -o program
```

## Практические советы

### ✅ DO (Делайте так):
1. Всегда используйте include guards
2. Минимизируйте зависимости в .h файлах
3. Используйте forward declaration где возможно
4. Документируйте публичный интерфейс в .h файле
5. Группируйте связанные функции в один модуль

### ❌ DON'T (Не делайте так):
1. Не пишите `using namespace std;` в .h файлах
2. Не определяйте большие функции в .h файлах
3. Не включайте ненужные заголовки
4. Не забывайте про const correctness
5. Не создавайте циклические зависимости
