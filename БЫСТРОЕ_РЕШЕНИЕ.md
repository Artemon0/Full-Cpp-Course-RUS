# ⚡ Быстрое решение: g++ не найден

## 🎯 Ваша ситуация

Вы говорите, что g++ установлен и добавлен в PATH, но PowerShell его не видит.

## 🔧 Решение за 30 секунд

### Вариант 1: Перезапустите PowerShell (САМОЕ ПРОСТОЕ)

1. **Закройте** текущее окно PowerShell/VS Code
2. **Откройте заново**
3. Проверьте: `g++ --version`

**Почему это работает?**  
PowerShell загружает PATH только при запуске. Если вы добавили путь в PATH, нужно перезапустить терминал.

---

### Вариант 2: Обновите PATH в текущей сессии

Запустите:
```cmd
.\ОБНОВИТЬ_PATH.bat
```

Или в PowerShell:
```powershell
$env:Path = [System.Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("Path","User")
```

Затем проверьте:
```powershell
g++ --version
```

---

### Вариант 3: Используйте полный путь

Если g++ установлен в `C:\msys64\mingw64\bin\`, используйте:

```powershell
C:\msys64\mingw64\bin\g++ --version
```

Если работает, значит проблема точно в PATH.

---

## 🔍 Диагностика

Запустите скрипт диагностики:
```powershell
.\ПРОВЕРКА_УСТАНОВКИ.ps1
```

Он покажет:
- Где находится g++
- Есть ли он в PATH
- Что нужно исправить

---

## 📋 Проверка PATH вручную

### В PowerShell:
```powershell
$env:Path -split ';' | Select-String -Pattern 'mingw|msys'
```

Должны увидеть строки типа:
```
C:\msys64\mingw64\bin
```

Если не видите - PATH не обновлен в текущей сессии.

### В CMD:
```cmd
echo %PATH% | findstr /i "mingw msys"
```

## ✅ После исправления

Проверьте, что все работает:

```powershell
# Проверка версии
g++ --version

# Быстрый тест компиляции
echo '#include <iostream>' > test.cpp
echo 'int main() { std::cout << "OK"; }' >> test.cpp
g++ test.cpp -o test.exe
.\test.exe
del test.cpp, test.exe
```

Должно вывести "OK".

---

## 🎓 Почему это происходит?

**PowerShell кэширует переменные окружения при запуске.**

Когда вы:
1. Открыли PowerShell
2. Установили g++
3. Добавили в PATH

PowerShell **не знает** об изменениях, потому что он уже запущен!

**Решение:** Перезапустить PowerShell.
